# Admin Portal API Reference

All routes below live under `admin/app/api/`. Every one (except the four
public/session-bootstrap auth routes) is gated by
`requirePermission()`/`getCurrentAdmin()` from `lib/apiGuard.ts` /
`lib/session.ts`: unauthenticated requests get `401`, requests missing the
named permission get `403`, and a permission listed in `lib/rbac.ts`'s
`STEP_UP_REQUIRED` also gets `403` with `{ stepUpRequired: true }` unless
the session has a fresh step-up (see below). Every mutating route writes
one `AuditLogEntry` via `lib/audit.ts`'s `writeAudit()` -- there is no
mutation in this app that bypasses that.

This is a reference for the routes as built, generated by reading the
actual `requirePermission(...)` call in each file rather than written
from memory, so it stays accurate as the source of truth (`lib/rbac.ts`
and each route file) evolves -- if the two ever disagree, the code wins.

## Auth (`/api/auth/*`)

| Method | Path | Auth | Notes |
|---|---|---|---|
| POST | `/api/auth/login` | Public | Email + password. Generic error on either a wrong email or wrong password. Locks the account for `ADMIN_STEP_UP_TTL`-independent 15 minutes after 5 failed attempts. Returns `nextStep: 'mfa' | 'mfa-setup'`. |
| POST | `/api/auth/mfa/verify` | Pending-MFA cookie | Completes login with a TOTP code or a one-time recovery code. |
| POST | `/api/auth/mfa-setup/start` | Pending-MFA cookie | Issues a new TOTP secret + QR code for first-time enrollment. |
| POST | `/api/auth/mfa-setup/confirm` | Pending-MFA cookie | Confirms the first TOTP code, enables MFA, issues the real session, returns one-time recovery codes. |
| POST | `/api/auth/step-up` | Session | Re-checks password + a fresh TOTP/recovery code; stamps `AdminSession.stepUpAt`, which `requirePermission()` checks against `ADMIN_STEP_UP_TTL_MINUTES`. |
| POST | `/api/auth/logout` | Session | Revokes the current `AdminSession`. |

## Error shape

Every route returns `{ error: string }` on failure, with the addition of
`{ error: string, stepUpRequired: true }` specifically for the "signed in,
has the permission, but step-up is stale" case -- `components/ConfirmActionButton.tsx`
and the handful of bespoke step-up-aware forms (`NewIncidentForm`,
`NewLegalHoldForm`, `NewAdminForm`, `AdminUserActions`) all key off that
flag to prompt for password + code and retry, rather than showing a raw
error.
